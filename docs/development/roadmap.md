## TRUE — measured constraints that bound every item below

- **Syscalls 0–95 are allocated; #95 `uptime_us` is the highest; the next free number is #96.** The ABI is frozen in `agnos-userland-abi.md`; the cyrius `syscalls_x86_64_agnos.cyr` peer mirrors it and must move in lockstep. `exit` is #0 on agnos, not Linux's 60 — a raw Linux number silently mis-dispatches (decision O5).
- **User memory is 2 MB huge pages only.** No 4 KB user PT level exists; `proc_map_page` writes a PD entry as `phys | 0x87`. `mmap` is therefore 2 MB-granular — `mmap(4096)` returns 2 MB. Low arena [0x10000000, 0x40000000); high arena [0x2000000000, 0x8000000000) via per-process PDPT[128..511].
- **Every process on a CPU enters syscalls on ONE shared per-CPU stack** — `pcpu_syscall_kstack_top = 0xF10000 + cpu*0x10000` (`syscall_hw.cyr`). Only the *interrupt* entry stack went per-process (1.46.1). This is why `preempt_disable()` guards every blocking sti-window and why `sched_yield`#44 abandons its frame.
- **Exec init stack: `rsp` starts at `stack_base + 0x3000` with `stack_base = 0x3FC00000`** — ~12 KB of usable downward stack out of a mapped 2 MB page. `iam`'s `main` carried ~17.6 KB of stack buffers, hard-faulted at CPL3, and never rendered (worked around app-side in iam 1.1.5).
- **16-process cap** (`proc.cyr:176`). `#37`/`#43` cap path and argv at **127 bytes** and env at **1024 bytes across 16 entries** (the argv *token* cap was raised 8→16 at 1.46.10).
- **Net:** 8 concurrent connections, 8 listeners; TCP RX ring 2048 B; `sock_recv`#49 returns **0 = WOULD_BLOCK and −1 = EOF**, inverted from Linux `EAGAIN`. `epoll` watches only `VFS_SIGNALFD` and `VFS_TIMERFD`, never sockets, and is 3-arg (no event struct, no per-fd data, no timeout).
- **Audio is playback-only and format-fixed.** `snd_config` accepts 44100 or 48000 Hz, 16-bit, stereo; resample lives in the producer, which binds every future audio consumer. `snd_open`#64 takes no direction argument (a1..a4 unused) and arms exactly one output stream off `hda_out_dac`.
- **One 2 MB PMM bitmap covers 16,777,216 pages ⇒ a 64 GB RAM ceiling.** Beyond it RAM is capped and logged, never silently dropped.
- **`initrd_init` is fed a fixed synthetic image** — `main.cyr:4978-4979` calls `initrd_build_test(0x6000)` then `initrd_init(0x6000)`; aarch64 uses 0x40700000. Nothing reads `boot_info`.
- **Standing boundaries (not work items, do not expire):** the in-kernel emergency shell is permanent, not transitional; kernel growth is per native workload — no POSIX `socket()` emulation, no foreign-ABI absorption; `fb_phys` is never exposed; **CWD is userland-owned — no `chdir`/`getcwd` syscall, and one is not to be added** (ABI §3.2, the 1.41.3 decision); `kriya` is the standalone `/bin` coreutils set and supersedes agnoshi's in-process FS builtins; agnsh AI/`hoosh` wiring is its own later arc; **cyrius is hands-off** — surface bugs, never edit that repo. Not in the queue at any horizon: Apple Silicon as a kernel-on-iron target (Asahi owns it), Landlock/seccomp/`unshare` ABI emulation, the GRUB/multiboot2 boot path (dead under strict W^X; gnoboot is the sovereign `BOOTX64.EFI`).

## FALSIFIED — closed or reverted; do not re-open without new evidence

- **"Only two execs per boot" — CLOSED.** Each `run` had permanently consumed 2 of the 6 usable 2 MB regions (code + stack), so the 4th run hit `pmm_alloc_2mb` exhaustion and printed `run: not an executable`. `proc_reap` / `proc_reap_child` now free the address space and all user pages on exit.
- **"A malformed on-disk ELF leaks page tables and mapped pages" — CLOSED at 1.41.6.** A PT_LOAD pre-pass validates every segment *before* `proc_create_address_space`, so a bad ELF returns with zero allocations to leak.
- **Multi-slot `proc_count` collapse ("while trailing-dead") — TRIED at 1.44.15 and REVERTED.** It reclaimed the slot of an exited-but-not-yet-`waitpid`'d proc, so the parent's `waitpid(pid)` found `pid >= proc_count` → −1 and that proc's address space leaked. A slot must persist until its OWN waitpid reaps it.
- **"`reboot`#13 is a stub that calls `arch_halt()`" — STALE.** #13 runs the real `power_sys` ACPI S5 / CF9 shutdown path, gated on the magic pair so the garbage-argument callers the old nullary ABI left behind fail closed. The missing update primitive is the boot slot, not the reboot.
- **"2D acceleration lands on the GFX ring" — WRONG.** It shipped as CP-DMA `DMA_DATA` on the MEC compute ring. SDMA was abandoned after six burns: the ring comes up first try and the F32 runs, but the engine never fetches (`cap 0` = the doorbell was never CAPTURED) — an agnos setup gap, **not** a hardware limit; Linux drives SDMA on this box. Resume state: `rptr 0 wptr 44 cnt 266269 base 4102029824 halt 0 cap 0 cntl 262146`.
- **Hardware-validation infra lost its only stated justification.** It existed to unblock SMP-AP-wake on real hardware; that shipped without it, validated by direct archaemenid burns in the 1.46.x arc. Needs a fresh rationale or re-siting as a 1.6x prerequisite.
- **Decade-map collision, unresolved.** The map assigns 1.5x to Intel, but the AMD dev line is at 1.56.x and has consumed it. The map already shifted once for this reason. Renumbering is a user call (`project_hardware_target_version_lines`) — surfaced, not fixed.
